## Задача

Рекомендовать пользователю десять треков, **которых он раньше не слышал** (discovery), и
сравнить на этой задаче пять моделей, реализованных с нуля. Из кандидатов исключается всё,
что пользователь слушал в обучающем окне, — поэтому знакомый трек не может попасть в выдачу
по построению, а не из-за штрафа.

Релевантным считается новый трек, проигранный в тестовом окне не меньше чем наполовину
(`played_ratio_pct >= 50`) — определение `Listen+` из карточки датасета.

Основная метрика, зафиксированная до подбора гиперпараметров — **NDCG@10** с нормировкой на
`idealDCG@min(10, число релевантных)`. Вторая метрика — **Recall@10**.

## Результаты на тесте

| № | модель | NDCG@10 | Recall@10 | HitRate@10 | гиперпараметры |
|---|---|---:|---:|---:|---|
| — | Random (контроль) | 0,00390 | 0,00099 | 3,5 % | — |
| — | Popularity (контроль) | 0,03988 | 0,01341 | 19,2 % | — |
| 1 | item-based kNN | 0,06731 | 0,02698 | 32,5 % | q = 0,7, k = 200 |
| 4 | FM с аудиоэмбеддингами | 0,07250 | 0,02816 | 37,9 % | dim = 64, lr = 0,05, 20 эпох BPR |
| 2 | iALS | 0,07278 | 0,02936 | 36,7 % | f = 128, reg = 0,05, α = 1 |
| 5 | Модель 5 (свой таргет) | 0,07501 | 0,02994 | 37,3 % | C = 20, β = 15 |
| **3** | **EASE** | **0,07836** | **0,03032** | 38,3 % | λ = 500 |

Метрика считается на 2 607 пользователях из 3 000 — у остальных либо нет профиля внутри
каталога, либо нет ни одной релевантной новинки в тестовом окне.

**Три вывода, если читать некогда.** Свой целевой сигнал действительно работает: модель 5 — тот
же алгоритм, что iALS, и единственное отличие в том, что считается положительным сигналом, —
обходит его так, что диапазоны трёх прогонов с разными зёрнами не пересекаются. Аудиоэмбеддинги
не добавили ничего, и абляция закрыла даже обходную гипотезу: склонность FM к незнакомым
исполнителям идёт от эмбеддинга артиста и парного лосса, а не от звука. А слабый штраф за
знакомого артиста при реранжировании почти бесплатен — у EASE доля новых артистов растёт с
40,7 % до 46,5 %, и точность при этом не падает.

формирование рекомендаций написано на numpy/scipy, включая факторизационную машину.

## Как запустить

```bash
pip install -r requirements.txt

# 1. данные (471 МБ) — в data/raw, в репозиторий не коммитятся
bash tools/download_data.sh

# 2. подвыборка: 3 000 пользователей x каталог 10 000 треков
python -I tools/build_subsample.py data/raw

# 3. аудиовекторы каталога (читаются удалённо, локально остаётся 9 МБ)
python -I tools/checks/f4_export_embeddings.py data/raw

# 4. модели: каждая считает свою сетку на val, затем финал на test
python -I models/run_popularity.py
python -I models/run_knn.py
python -I models/run_ease.py
python -I models/run_ials.py
python -I models/run_model5.py test
python -I models/fm_one.py test audio

# 5. анализ по артистам и кривая реранжирования
python -I models/run_analysis.py
```

Полный файл эмбеддингов Yambda весит 13,8 ГБ, и целиком он не нужен: `tools/checks/f4_export_embeddings.py`
читает его по сети с отбором колонок и оставляет векторы только для 10 000 треков каталога.

**Данные.** Репозиторий их не содержит и не копирует. Код ищет каталог данных в таком порядке:
переменная окружения `YAMBDA_DATA`, затем `data/` рядом с кодом, затем `../hw1/data` — см.
`models/common.py`, функция `data_dir()`. Если данные уже скачаны в другое место:

```bash
YAMBDA_DATA=/путь/к/data python -I models/run_ease.py
```

**Воспроизводимость.** Все случайные зёрна зафиксированы: отбор подвыборки — 42, инициализация
факторов — 42, отрицательные примеры BPR — 0. Разбиение временное, границы окон заданы в сутках
в `models/common.py`.
