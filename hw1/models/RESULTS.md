**Все пять моделей написаны с нуля**, готовых реализаций рекомендательных моделей в работе
нет. ALS — `run_ials.py`: формулировка Hu-Koren-Volinsky, точное решение полушагов через
`np.linalg.solve`, накопление матрицы батчами с паддингом по длине строк.

**Проверка корректности своей реализации.** Чтобы убедиться, что ALS сходится к тому же
решению, что и эталонная реализация метода, одни и те же данные были один раз прогнаны через
библиотечный `implicit.als` — исключительно как сверка, в саму работу он не входит и в
зависимостях его нет. При одинаковых параметрах (f = 128, 5 итераций) своя реализация даёт
на val 0,07225, эталонная на 20 итерациях — 0,07353; на тесте своя при f = 128 даёт 0,07278
против 0,07347 у эталонной при f = 256. Разница 0,0007 объясняется меньшим числом факторов и
более узкой сеткой (почему она узкая — ниже); расхождение записано как есть, без подгонки.

**Разброс между запусками** (`run_spread.py`, три случайных зерна на test):

| модель | прогоны | размах | среднее |
|---|---|---:|---:|
| iALS | 0,07278 / 0,07231 / 0,07229 | 0,0005 | 0,07246 |
| Модель 5 | 0,07501 / 0,07665 / 0,07492 | **0,0017** | 0,07553 |

У kNN и EASE разброса нет вовсе: обе детерминированы, случайной инициализации в них нет.
У FM он не измерялся.

**Что из этого можно утверждать, а что нет.**

* **Модель 5 лучше базового iALS — твёрдо.** Диапазоны не пересекаются: худший её прогон
  (0,07492) выше лучшего прогона iALS (0,07278), запас 0,0021.
* **EASE лучше модели 5 — вероятно, но не доказано.** EASE даёт 0,07836 и выше всех трёх
  прогонов модели 5, однако отрыв от лучшего из них (0,07665) равен 0,0017 — ровно порядок
  собственного разброса модели 5. Утверждать первое место EASE по NDCG@10 можно, настаивать
  на размере отрыва — нет.
* **Остальные разрывы крупные и безопасные:** все персональные модели почти вдвое лучше
  Popularity, тот в десять раз лучше случайной выдачи, kNN отстаёт от EASE на 0,011.

Отдельно стоит отметить, что **у модели 5 разброс втрое больше, чем у iALS на той же
реализации**. Похоже, дело в самом таргете: у него тяжёлый правый хвост (максимальный вес 35
против обычных единиц-двоек у числа прослушиваний), и решение сильнее зависит от начальной
инициализации факторов.

## FM: аудиоэмбеддинги ничего не добавляют

**Абляция на val при равном бюджете в 20 эпох:**

| вариант | NDCG@10 | Recall@10 | HitRate@10 |
|---|---:|---:|---:|
| FM без аудио (id трека + артист) | **0,06936** | 0,02349 | 36,5 % |
| FM с аудио (id + аудио + артист) | 0,06823 | 0,02294 | 36,3 % |

Разница 0,0011 — примерно втрое больше разброса между запусками (≈ 0,0004), так что это не шум:
**аудиовектор не помогает, а слегка мешает.** Ровно это и предсказывал блок 07: каталог
отбирается по популярности, полностью холодных треков в нём нет по построению, а у популярного
трека коллаборативный сигнал богаче любого контентного. Аудио обосновывалось как контентный
признак, а не как средство против холодного старта, и большого выигрыша от него не ожидалось.

**Абляция на test, включая срез «новый артист»** (`fm_ablation.py`). Сначала отчёт оговаривал,
что абляция мерилась только по общей метрике, поэтому отнести новизну выдачи FM именно к аудио
было нельзя. Теперь измерено, и ответ отрицательный:

| вариант | NDCG@10 | Recall@10 | новых артистов в топ-10 | из топ-100 | Recall@10 на срезе «новый артист» |
|---|---:|---:|---:|---:|---:|
| FM с аудио | 0,07250 | 0,02816 | 44,4 % | 15,2 % | 0,02252 |
| FM без аудио | **0,07277** | **0,02911** | **44,6 %** | 15,1 % | **0,02315** |

Ветвь без аудио не хуже ни по одному показателю новизны, и со штрафом за знакомого артиста
обе ведут себя одинаково: при μ = 0,25 доля новых артистов 64,8 % против 64,7 %, при μ = 1 —
96,9 % против 97,0 %, Recall@10 на срезе 0,04128 против 0,04133. Все расхождения в пределах
разброса между запусками. **Значит сдвиг FM к незнакомым исполнителям даёт не звук, а
эмбеддинг артиста и парная функция потерь BPR — они есть в обеих ветвях.** Аудиопризнак не
добавляет ни точности, ни новизны.

**Оговорка про бюджет обучения.** Число эпох не подбиралось. На промежуточном замере FM с аудио
давала на val 0,07027 уже после 3 эпох, то есть к 20 эпохам результат не вырос, а упал
(0,06823) — оптимум по эпохам, скорее всего, раньше, и обе ветви абляции могут быть
недообучены или переобучены одновременно. Вывод «аудио не помогает» держится на равенстве
бюджета у обеих ветвей, а не на том, что каждая обучена до своего оптимума.

**О починке.** Первая версия модели расходилась и давала ровно нулевые метрики: градиент
проекции `W` суммировался по всему мини-батчу из 32 768 примеров, тогда как остальные параметры
обновляются построчно через scatter, то есть уже «на пример». Шаг для `W` оказывался на четыре
порядка больше, веса уходили в бесконечность, а сигмоида BPR переполнялась. Исправлено делением
этого градиента на размер батча плюс клип аргумента экспоненты; после починки `|W|` не превышает
0,032, а все оценки конечны.

## Подбор на val

**EASE по λ:** 50 → 0,07373; 100 → 0,07515; 250 → 0,07616; **500 → 0,07763**; 1000 → 0,07734;
2500 → 0,07645. Кривая плоская, оптимум широкий.

**kNN по (q, k)** — q подавляет популярность, k отсекает соседей:

| q | k = 50 | k = 100 | k = 200 | k = 500 |
|---|---:|---:|---:|---:|
| 0,3 | 0,06011 | 0,06075 | 0,06532 | 0,06611 |
| 0,5 | 0,06368 | 0,06608 | 0,06990 | 0,06893 |
| **0,7** | 0,06670 | 0,06949 | **0,07096** | 0,06556 |
| 0,9 | 0,06623 | 0,06825 | 0,06856 | 0,06542 |

Оптимум внутри сетки, а не на краю: q = 0,9 хуже q = 0,7 на всех k, k = 500 хуже k = 200 при
q ≥ 0,7. Подавление популярности помогает заметно (0,0709 при q = 0,7 против 0,0653 при
q = 0,3) — в discovery соседями иначе оказываются хиты, а рекомендовать надо незнакомое.

**iALS: пространство поиска и почему оно такое.** Своя реализация считает ощутимо медленнее
библиотечной — 2,4 минуты на обучение при factors = 64 и 10,5 минут при 128, — поэтому прежняя
сетка из 27 комбинаций целиком не прогонялась. Порядок подбора: сначала reg × α при дешёвом
factors = 64 (девять комбинаций), затем проверка, помогает ли удвоение factors при лучших
(reg, α). Сокращение опирается на прежний замер библиотечной версии, где α решала всё, reg
почти не влиял, а factors 128 и 256 различались в пятом знаке.

| reg | α = 1 | α = 10 | α = 40 |
|---|---:|---:|---:|
| 0,01 | 0,07018 | 0,06052 | 0,04440 |
| **0,05** | **0,07019** | 0,06116 | 0,04397 |
| 0,2 | 0,06966 | 0,06055 | 0,04255 |

Затем factors при reg = 0,05, α = 1: 64 → 0,07019, **128 → 0,07249**.

**α решает всё, и это содержательный результат.** α = 1 выигрывает при всех трёх reg с
огромным отрывом (0,070 против 0,061 и 0,044), а reg между 0,01 и 0,2 меняет метрику в
четвёртом знаке. В discovery-постановке «слушал ли вообще» несёт больше, чем «сколько раз»:
уверенность, пропорциональная числу прослушиваний, только вредит. Оговорка: α = 1 стоит на
краю сетки, меньшие значения не проверялись.

**Модель 5, три варианта коэффициентов** (форма формулы — из блока 05, см. [`target.py`](target.py)):

| вариант | C | β | масса таргета от лайков | верхние 2,5 % пар | NDCG@10 на val |
|---|---:|---:|---:|---:|---:|
| A (повторы главные) | 20 | 5 | 10,3 % | 18,1 % | 0,07402 |
| **B (принят)** | 20 | 15 | 25,6 % | 22,5 % | 0,07448 |
| C (лайк главный) | 10 | 30 | 44,7 % | 27,5 % | 0,07455 |

Все три бьют обычный iALS (0,07249 на val при тех же factors, reg, α), но между собой
различаются в пределах шума: размах 0,0005 при разбросе между запусками того же порядка.
То есть выигрыш даёт сам факт переопределения положительного сигнала, а не точное значение
β — выбор β остаётся вопросом смысла модели, а не метрики.

Вариант B выбран 27.10.2026: β = 15 — тот уровень повторов, на котором P(лайк)
достигает 40 %, а верхние 2,5 % пар держат 22,5 % массы, ниже порога 26,1 %, которым блок 05
предупреждал о перекосе. Лайков «при знакомстве» 83 739 на 1 674 414 пар обучающего окна val
и 93 717 на 1 835 987 пар окна test.

## Как воспроизвести

Порядок важен: каждый из прогонов на стадии test оставляет свою матрицу оценок
(`scores_*.npy`), а `run_analysis.py` их читает и ничего не переобучает.

```bash
python -I models/run_popularity.py          # контроль: Popularity и случайная выдача
python -I models/run_knn.py                 # сетка (q, k), затем test
python -I models/run_ease.py                # сетка по lambda, затем test
python -I models/run_ials.py                # сетка reg x alpha, проверка factors, затем test
python -I models/run_model5.py              # три варианта таргета на val
python -I models/run_model5.py test         # принятый вариант B на test
python -I models/fm_one.py val audio        # FM с аудио на val
python -I models/fm_one.py val noaudio      # абляция: та же модель без аудио
python -I models/fm_one.py test audio       # FM на test
python -I models/fm_one.py test noaudio     # ветвь абляции на test
python -I models/run_analysis.py            # артисты и сетка по mu
python -I models/fm_ablation.py             # абляция FM по срезу «новый артист»
python -I models/run_spread.py              # разброс между запусками
```

Файлы: [`common.py`](common.py) — данные, кандидаты, метрики, поиск каталога данных;

`YAMBDA_DATA`, затем `data/` рядом с кодом, затем `../hw1/data`. Репозиторий сдачи данные не
содержит и не копирует — 523 МБ остаются там, где скачаны.
